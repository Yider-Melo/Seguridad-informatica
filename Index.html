Vulnerabilidades y amenazas en la web

Las vulnerabilidades web representan debilidades intrínsecas, fallos de diseño o errores de implementación en aplicaciones, servidores, infraestructura o procesos que componen el ecosistema web. Estas deficiencias crean puertas de acceso no autorizado que pueden ser descubiertas y explotadas por actores malintencionados. No son meros "errores de programación", sino brechas sistémicas que comprometen la integridad, confidencialidad y disponibilidad de los sistemas.

Las amenazas web constituyen acciones, eventos o actividades maliciosas deliberadas que buscan explotar vulnerabilidades existentes para comprometer sistemas web. Representan la materialización del riesgo potencial y encarnan la intencionalidad detrás de los ataques cibernéticos.

OWASP Top 10 - Vulnerabilidades Web Críticas

1. Fallos de Control de Acceso (Broken Access Control)

¿Qué es? Fallos que permiten a los usuarios actuar fuera de sus permisos intencionados (ej.: ver datos de otros usuarios, modificar información, acceder a funciones de administrador).

Ataque Relacionado: Escalada de privilegios vertical/horizontal.

Ejemplo: Cambiar el ID de usuario en la URL de miperfil.com/user?id=123 a miperfil.com/user?id=124 para ver la cuenta de otra persona.

2. Fallos Criptográficos (Cryptographic Failures)

¿Qué es? Fallos relacionados con la protección de datos sensibles. Anteriormente se llamaba "Exposición de Datos Sensibles".

Ataque Relacionado: Robo de información.

Ejemplo: Transmitir contraseñas o números de tarjetas de crédito sin cifrar (HTTP en lugar de HTTPS), o usar algoritmos de cifrado débiles o obsoletos.

3. Inyección (Injection)

¿Qué es? Cuando un atacante puede enviar datos hostiles a un intérprete (como una base de datos) y este los ejecuta.

Ataque Relacionado: Inyección SQL (la más común), Inyección OS Command, LDAP Injection.

Ejemplo: En un formulario de login, escribir ' OR '1'='1'-- para burlar la autenticación y acceder como administrador.

4. Diseño Inseguro (Insecure Design)

¿Qué es? Fallos que surgen por una falta de prácticas de seguridad durante la fase de diseño de la aplicación. Es un riesgo nuevo en el Top 10.

Ataque Relacionado: Depende del fallo de diseño.

Ejemplo: Un flujo de recuperación de contraseña que se basa en preguntas de seguridad cuya respuesta es fácil de adivinar o investigar (¿Cuál es el nombre de tu mascota?).

5. Configuración de Seguridad Incorrecta (Security Misconfiguration)

¿Qué es? Configuraciones inseguras en cualquier parte de la pila tecnológica (servidor web, base de datos, frameworks, etc.).

Ataque Relacionado: Acceso no autorizado.

Ejemplo: Dejar los directorios del servidor con listado activo (se pueden ver todos los archivos), usar contraseñas por defecto, o tener páginas de error que revelen información sensible (versiones de software).

6. Componentes Vulnerables y Obsoletos (Vulnerable and Outdated Components)

¿Qué es? Usar librerías, frameworks o otro software con vulnerabilidades conocidas.

Ataque Relacionado: Explotación de vulnerabilidades públicas.

Ejemplo: Una aplicación que usa una versión antigua de jQuery o de un CMS como WordPress con plugins desactualizados que tienen vulnerabilidades explotables.

7. Fallos de Identificación y Autenticación (Identification and Authentication Failures)

¿Qué es? Fallos en los mecanismos de login y gestión de sesiones.

Ataque Relacionado: Robo de cuentas, suplantación de identidad.

Ejemplo: Credenciales por defecto ("admin/admin"), permitir contraseñas débiles, no invalidar sesiones correctamente después del logout, o ser vulnerable a ataques de fuerza bruta.

8. Fallos en el Software y la Integridad de los Datos (Software and Data Integrity Failures)

¿Qué es? Fallos que asumen que el software o los datos de origen son confiables sin verificar su integridad.

Ataque Relacionado: Ataques de la cadena de suministro (Supply Chain Attacks).

Ejemplo: Una aplicación que actualiza automáticamente desde un repositorio no seguro, o que usa plugins/librerías de fuentes no verificadas que han sido comprometidas.

9. Fallos en el Registro y Monitoreo de la Seguridad (Security Logging and Monitoring Failures)

¿Qué es? No registrar adecuadamente las actividades de seguridad o no monitorearlas para detectar incidentes.

Consecuencia: Los ataques pasan desapercibidos durante mucho tiempo.

Ejemplo: No tener logs de los intentos de login fallidos, lo que impide detectar un ataque de fuerza bruta.

10. Falsificación de Peticiones en Sitios Cruzados (SSRF - Server-Side Request Forgery)

¿Qué es? Cuando una aplicación web es engañada para que realice una petición a una dirección interna o externa no intencionada.

Ataque Relacionado: Acceso a sistemas internos.

Ejemplo: Una aplicación que permite al usuario introducir una URL para obtener una vista previa de un enlace, pero en su lugar es manipulada para acceder a http://localhost/admin (la consola de administración interna del servidor).
